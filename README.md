# Liara SQL Server Backup Manager

داشبورد فارسی RTL برای بکاپ‌گیری دیتابیس مدیریت‌شده لیارا، نگهداری روی دیسک سرور و ارسال اختیاری به Telegram با SOCKS5.

## راه‌اندازی

```bash
npm install
cp .env.example .env
# Edit .env. Generate secrets:
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
# Use different random values for ENCRYPTION_KEY and SESSION_SECRET
set -a; . ./.env; set +a
npm start
```

در حالت پیش‌فرض پنل در `http://127.0.0.1:3000` باز می‌شود. برای دسترسی از بیرون، پشت HTTPS reverse proxy با کنترل دسترسی نصب شود. برای کانتینر یا VPS از دیسک دائمی برای DATA_DIR استفاده کنید. اگر از HTTPS reverse proxy مطمئن استفاده می‌کنید `TRUST_PROXY=true` و `HOST=0.0.0.0` تنظیم کنید. **هرگز برنامه را بدون TLS عمومی نکنید.**

از داخل UI: Database ID و توکن جدید API لیارا، تنظیمات SQL، زمان‌بندی، Telegram و SOCKS را مشخص کنید. توکن موجود در گفتگوی قبلی افشا شده و باید از پنل لیارا باطل و جایگزین شود. رمز SQL Server از رشته اتصال ناقص کاربر معلوم نیست؛ آن را دستی در UI وارد کنید.

## منطق بکاپ

1. API لیارا: `POST /v1/databases/{id}/backups`، `GET /v1/databases/{id}/backups`، `POST /v1/databases/{id}/backups/{name}/download`.
2. بعد از دستور ایجاد، برنامه تا چهار دقیقه برای ظاهرشدن شناسه جدید در لیست polling می‌کند.
3. لینک دریافت‌شده را محدود به دامنه‌های مورد اعتماد می‌کند و با محدودیت ۲ GiB در DATA_DIR/backups ذخیره می‌کند.
4. ارسال خودکار در بکاپ‌های زمان‌بندی‌شده فعال است؛ ارسال بکاپ دستی با گزینه جداگانه فعال می‌شود.
5. تاریخچه محلی تا تعداد تعیین‌شده در تنظیمات نگهداری می‌شود. دکمه دانلود آخرین بکاپ، جدیدترین فایل ذخیره‌شده روی دیسک را می‌دهد.

**مهم:** این ابزار بکاپ native `.bak` را فقط در صورتی ایجاد می‌کند که API لیارا برای پلن/موتور SQL Server شما آن را ارائه دهد. این ابزار فرمان `BACKUP DATABASE` را روی اتصال T-SQL اجرا نمی‌کند، چون فایل آن روی filesystem سرویس مدیریت‌شده نوشته می‌شود، نه روی سرور Node. خروجی دانلود ممکن است بسته به موتور/نسخه API الزاماً فرمت `.bak` نباشد؛ اسم فایل در نسخه حاضر با پسوند `.bak` ذخیره می‌شود و باید قبل از استفاده در فرایند restore نوع آن را اعتبارسنجی کنید. دکمه تست SQL فقط اعتبار اتصال را بررسی می‌کند. بدون Database ID نمی‌توان از رشته اتصال تنها به Liara API برای ایجاد بکاپ دسترسی داشت.

## Telegram

- با BotFather توکن ربات بسازید، ربات را به chat اضافه کنید و Chat ID را در UI وارد کنید.
- مقدار proxy پیش‌فرض `socks5h://127.0.0.1:7890` است؛ آدرس `127.0.0.0.1` اشتباه است.
- پورت 7890 باید روی **همان دستگاه/کانتینر برنامه Node** در دسترس باشد. اگر پراکسی روی میزبان Docker اجرا می‌شود، 127.0.0.1 کانتینر به میزبان اشاره نمی‌کند.
- محدودیت اندازه آپلود Bot API تلگرام ممکن است از فایل بکاپ کمتر باشد. برای فایل بزرگ، Object Storage بهتر است. در این نسخه آپلودهای بزرگ به Telegram ممکن است خطا بدهند.

## نکات عملیاتی

- همه endpointهای عملیات و دانلود محافظت‌شده با session و CSRF هستند. توکن‌های ذخیره‌شده با AES-256-GCM و ENCRYPTION_KEY رمزنگاری می‌شوند. کلید خارج از پوشه data نگهداری شود.
- برای تولید، بهتر است session store پایدار (Redis) به جای MemoryStore پیش‌فرض Express Session و سیاست پشتیبان‌گیری از پوشه data اضافه شود.
- cron با منطقه‌زمانی تنظیم‌شده اجرا می‌شود؛ نمونه `0 3 * * *` یعنی ۳ صبح هر روز. scheduler فقط وقتی برنامه در حال اجراست فعال است.
- دانلود لینک دارای redirect غیرفعال است و فقط HTTPS دامنه‌های Liara یا Amazon S3 مجاز است. اگر URL امضاشده لیارا میزبان دیگری داشته باشد باید allowlist در کد بازبینی شود.
- تنظیمات host/port، رمز ورود، لیارا، تلگرام و زمان‌بندی از UI تغییر می‌کنند. تنظیمات زیربنایی شامل HOST، PORT، ENCRYPTION_KEY، SESSION_SECRET و DATA_DIR صرفاً از env قابل تغییرند تا UI نتواند دیسک یا امنیت سرویس را تغییر دهد.
- این نمونه را پیش از استفاده عملیاتی با بکاپ آزمایشی و **restore آزمایشی** تأیید کنید. فرایند بکاپ‌های بسیار بزرگ و چندساعته نیازمند صف کار پایدار است.
